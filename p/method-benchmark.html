Independent audit: PASS

Public data shows where laboratory-result meaning needs explicit handling.

WeedDAO's benchmark inspected a public New York cannabis-results extract and Washington State's CCRS lab-upload format. An independent audit verified the five observational findings below. This validates the benchmark evidence — not yet a production WeedDAO transformation.

330public COA rows
16,357parsed result objects
13Washington CSV fields
1. Result state cannot always be represented as a number The public parsed corpus contained 5,251 exact ND values and 4,943 exact <LOQ values, plus 1,220 qualified numeric strings such as <0.1. A numeric-only destination cannot preserve those distinctions without additional semantics.
2. The same concept can arrive under different field shapes Within one public parser path, cannabinoid results used unit while other panels used units. Another parser path omitted both keys. This is a downstream representation issue, not a claim about any laboratory's native LIMS.
3. Display labels are not stable identifiers The audit found 60 canonical keys associated with multiple display names. Most were case or punctuation variants, but some were materially different labels — for example one public key grouped Borneol, (+)-Borneol, and (-)-Borneol.
4. Parsed COA data needs provenance and review controls A conservative rule flagged 632 result-shaped objects containing likely extraction artifacts such as page furniture, split analyte names, prose, or identifier-like strings in limit fields. These artifacts belong to the public parsing layer and are not attributed to the source laboratories.
5. Regulatory CSVs can depend on semantics outside the row Washington's public CCRS LabTest.csv has 13 columns, including TestName, TestValue, and LabTestStatus, but no dedicated unit, LOD, or LOQ columns. The companion guide supplies those rules externally: the unit is encoded in TestName, and non-detects are represented in TestValue as < plus the numeric LOQ.
What this supports:
An interoperability layer should preserve raw values and provenance, separate qualified result states from numeric measurements, normalize identifiers and unit fields, and flag ambiguous mappings for review.

What this does not prove yet: that a WeedDAO production path has preserved these semantics end-to-end. That is the next validation step.
